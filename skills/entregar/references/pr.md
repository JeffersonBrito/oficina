# Modelo de PR

Título: igual ao commit principal. Frase curta em inglês, capitalizada, sem prefixo.

Corpo, em inglês, derivado da task do `/lapidar`:

```markdown
## Why
<one or two sentences: the problem or the goal, from the task's Contexto and Objetivo>

## What changed
- <one line per meaningful change, in the order a reviewer should read>

## Out of scope
- <what was deliberately left out, from the task's Não inclui, and where it goes next>

## How to verify
```bash
<exact commands, from the task's Como verificar>
```
- <manual checks, if any: what to call and what to expect>
```

Regras:
- Sem seção vazia: remover, não escrever "N/A".
- Sem rodapé de atribuição, sem emoji de ferramenta, sem "generated by".
- "How to verify" tem comandos que rodam de verdade; o `/conferir` já rodou todos.
- Se o PR fecha uma issue, `Closes #N` na última linha do corpo.

Exemplo:

```markdown
## Why
Users could not create credentials without manual database inserts. This adds the registration endpoint from the auth task.

## What changed
- `POST /auth/register` with email and password validation
- Unique index on `users.email`; duplicate email returns 409
- Passwords stored with bcrypt, never returned in responses
- Swagger entry with 201, 400 and 409

## Out of scope
- Login and JWT issuance (next task)
- Email confirmation and password recovery

## How to verify
```bash
npm run test -- --testPathPattern=auth
npm run lint
```
- `POST /auth/register` twice with the same email: first 201, second 409
```
